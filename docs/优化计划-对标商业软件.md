# Remote Agent Studio 优化计划(对标商业软件)

> 版本:2026-07-16 · 基线:v0.1.0(本轮已完成 14 项修复/功能后的状态)
> 对标对象:Termius(SSH 管理)、VS Code Remote-SSH(远程开发)、Cursor / Codex Desktop / Claude Desktop(Agent 交互)、Warp(终端体验)

## 实施进度(2026-07-16)

- [x] **任务闭环**：对话可创建任务，任务具备草稿、执行、待验收、验收通过、需修改、失败与人工接管状态；任务及交付证据独立原子持久化。
- [x] **交付与审计**：将 diff、产物、用量、命令风险等级、危险命令、权限变更和人工停止记录到任务中；任务页支持验收、返工和主机级用量汇总。
- [x] **三层权限**：新增 Plan Mode（Codex `read-only` 沙箱 / Claude `plan` 权限），保留受限工作区和显式确认的 System Mode；命令旁显示风险等级。
- [x] **启动性能**：聊天、文件、终端、任务、环境配置面板按需加载，入口构建产物由约 513 kB 降至约 175 kB。
- [x] **文件传输基础可靠性**：支持拖拽、单文件及双向目录递归传输、失败后的单文件断点续传、汇总进度与单传输取消；跨面板的独立任务中心支持查看、取消和重试。目录传输会跳过符号链接，避免越出用户选择的源目录。
- [x] **i18n 基础**：语言偏好可持久化；设置、导航、任务交付/状态/风险标签及文件传输核心控制支持中英文，页面语言属性会在启动时恢复。聊天、终端和配置业务面板仍按模块推进。
- [x] **工程基线**：CI、逐字流式、Diff、长对话窗口化、搜索/导出、多标签终端、传输与诊断导出已在当前代码库中覆盖；Electron 43 与 electron-builder 26 已升级，锁定依赖的 npm 安全审计为 0 漏洞。

仍待外部条件满足后执行：逐条审批需要切换到支持双向授权回调的 Agent SDK/长连接协议；应用签名、公证、自动更新需要对应平台证书、更新源和发布策略。不要把现有非交互 `exec` 的失败提示误称为“弹窗批准一条命令”。

## 一、现状盘点

**架构**:Electron(main:IPC 路由 + ssh2/SFTP/反向隧道/安装器/Agent 会话)+ React/zustand 渲染层,每轮对话 = 一次 `codex exec --json` / `claude -p stream-json` 非交互执行 + 会话 ID resume。

**已具备的差异化能力**(商业软件没有的组合,是核心卖点):
- SSH 一键接入远程机直接对话式使用 codex/claude,自动装 CLI、自动配代理(反向隧道/局域网直连)、本机认证一键下发
- 双引擎同对话切换 + 上下文接力;排队发送;全自动模式(自动确认 + 熔断)
- 文件树/双栏 SFTP + 应用内文本/图片/Markdown 阅读预览;附件与生成图片回收
- 本地模式与用户终端环境完全同源(交互式登录 shell 环境抓取)

**本轮已还清的债**:注入类安全隐患、codex 精确 resume、Electron prompt() 失效、平台错配依赖自愈、远程下载器直连/代理回退、$HOME 解析污染、React #185、确认循环。

**与商业软件的主要差距**(按用户可感知程度排序):
1. 输出不是逐字流式,一段一段跳出(Cursor/Desktop 是 token 级流式)
2. workspace 模式下无交互式审批:命令要么被沙箱拒绝,要么开全自动,没有"弹窗批准这一条"(Desktop 核心体验)
3. 文件修改没有 diff 视图,只有文件名列表(Cursor 的红绿 diff 是标配)
4. SSH 无主机指纹校验(MITM 风险),断线不自动重连(Termius/VS Code 标配)
5. 对话历史全量 JSON 重写 + 消息列表无虚拟化,长对话会卡
6. 无签名/公证/自动更新,分发即"来历不明的应用";无崩溃上报
7. 传输尚缺目录级断点续传；i18n 尚未覆盖聊天、终端和配置业务面板

## 三、技术债清单(随手修,不排期)

- agent 取消已记录远端 PID，并通过 TERM→延迟 KILL 兜底；后续仅需在真实服务器上做断网/高负载场景验证
- 终端 shell 与对话共用一个 SSH 连接,重负载互相争带宽,可选独立连接
- `fs:listLocal/readdirSync` 在 main 进程同步 IO,大目录会卡主进程,改 fs.promises
- Message 组件 key 用数组下标,插入历史时会错位重挂
- `启动.command` 与 README 未覆盖 Windows 启动路径(launch-remote-agent-studio.cmd 内容极简)
- store.js 单文件已 300+ 行,拆分 conversations/hosts/queue 三个 slice

## 四、风险与明确不做

- **不做** PTY 抓屏式交互(维持 exec+resume 架构):脆弱且难测试,审批体验用 1.2 的协议方案解决
- **风险**:codex app-server/proto 协议无稳定性承诺,1.2 的 codex 部分建议放在 claude 验证通过之后
- **风险**:上下文接力受模型输入上限约束,超长对话摘要需二次压缩(可用 map-reduce 摘要,P3 再做)
