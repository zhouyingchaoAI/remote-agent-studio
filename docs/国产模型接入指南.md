# 国产模型接入指南

> Chinese LLM Setup Guide — English summary at the bottom.

Remote Agent Studio 提供两条国产模型路线,可并存、可同对话切换:

**路线 A · DeepSeek 直驱 Claude Code**(引擎「◈ DeepSeek」):用 DeepSeek 官方 Anthropic 兼容端点驱动 Claude Code CLI,保留 Claude Code 全部生态能力(含官方 Web Search)。适合只用 DeepSeek 的用户。

**路线 B · 国产模型统一引擎**(引擎「▣ 国产模型(Grok)」):用 xAI 开源的 grok CLI 作统一 harness,DeepSeek / 智谱 GLM / 月之暗面 Kimi / 通义 Qwen 以及任意 OpenAI 兼容中转站都能接。适合多模型切换、比价、用中转站的用户。

两条路线的配置都在**图形界面**完成,不需要手改任何配置文件。

## 准备:获取 API Key

| 厂商 | 开放平台 | 界面里对应的变量 |
|---|---|---|
| DeepSeek | platform.deepseek.com → API Keys | `DEEPSEEK_API_KEY` |
| 智谱 GLM | open.bigmodel.cn → API 管理 | `ZHIPU_API_KEY` |
| 月之暗面 Kimi | platform.moonshot.cn → API Key | `MOONSHOT_API_KEY` |
| 通义 Qwen | 阿里云百炼 dashscope → API-KEY | `DASHSCOPE_API_KEY` |

## 路线 A:DeepSeek 直驱 Claude Code

先在「环境配置」页确认 Claude Code 已安装(没有就点一键安装)。在「API Key」区选 `DEEPSEEK_API_KEY(DeepSeek)`,粘贴 key,点「写入远程」。点「测试远程 DeepSeek」,看到"可用"即通。新建对话选「◈ DeepSeek」引擎即可;模型默认 `deepseek-v4-pro[1m]`,下拉可切 `deepseek-v4-flash`。

原理:应用在启动 claude CLI 时注入 `ANTHROPIC_BASE_URL=https://api.deepseek.com/anthropic` 与 `ANTHROPIC_AUTH_TOKEN`(取自你写入的 key),子代理/轻量任务自动走 flash 降本。注意 DeepSeek 旧模型名 `deepseek-chat` / `deepseek-reasoner` 已于 2026-07-24 退役,本应用已使用 V4 命名。

## 路线 B:国产模型统一引擎(grok CLI)

第一步,「环境配置」页点「一键安装 Grok CLI」(官方独立二进制,自动走你配置的代理)。

第二步,在「国产模型(Grok)端点配置」区,给你要用的厂商填 API Key,点「写入 Key」——每写一次都会自动同步远程 `~/.grok/config.toml` 的受管配置块。

第三步,点「测试国产模型(Grok)」验证(默认用 DeepSeek 测试)。

第四步,新建对话选「▣ 国产模型(Grok)」引擎。模型下拉预设了 `deepseek/deepseek-v4-pro`、`deepseek/deepseek-v4-flash`、`glm/glm-5`、`kimi/kimi-k2.5`、`qwen/qwen3.5-coder`;各家模型名迭代快,如与你账号可用的不符,选「自定义…」直接输入 `glm/glm-5.2` 这类新名字即可,配置块会自动补上对应条目。

### 接中转站 / 任意 OpenAI 兼容服务

在「国产模型(Grok)端点配置」区展开「+ 添加自定义端点」,填五项:显示名(如"我的中转站")、模型 ID(如 `deepseek-v4-pro`)、base_url(如 `https://xxx.example.com/v1`)、协议(OpenAI 兼容选 `chat_completions`,Anthropic 系选 `messages`)、env 变量名(如 `MY_RELAY_API_KEY`)+ 可选直接填 Key。点「添加并同步」后,聊天界面的模型下拉会出现「我的中转站(自定义)」。

### 安全设计

API Key 一律写入远程 `~/.remote-agent-env.sh`(600 权限),`config.toml` 里只引用 `env_key` 变量名,永不落明文;受管配置块带标记注释、整块重写,你手写在块外的配置不会被动。配了自定义模型后 grok CLI 无需 xAI 账号登录。

## 两条路线怎么选

只用 DeepSeek、想要 Claude Code 生态(Web Search、skills)→ 路线 A。多家模型来回切、比价、用中转站、想要 OS 级沙箱(grok `--sandbox workspace`)→ 路线 B。两条可同时配好,在同一对话里随时切换引擎,上下文自动接力。

## 常见问题

测试报 401/认证失败:key 写错或该厂商余额不足,重写一次 key 再测。测试报模型不存在:该厂商改了模型名,用「自定义…」输入新模型 ID。远程连不上厂商 API:先在「环境配置」页把代理配置应用并测试通过(国内服务器直连各家国内端点一般无需代理;连 Anthropic/OpenAI 才需要)。

## English Summary

Two routes for Chinese LLMs, both fully GUI-configured (no config-file editing):

**Route A — DeepSeek driving Claude Code.** Setup page → write `DEEPSEEK_API_KEY` → test → create a conversation with the DeepSeek engine. Under the hood the app injects DeepSeek's official Anthropic-compatible endpoint (`api.deepseek.com/anthropic`) into the claude CLI. Default model `deepseek-v4-pro[1m]`.

**Route B — Unified engine via grok CLI.** Setup page → one-click install grok CLI → enter provider API keys (DeepSeek / GLM / Kimi / Qwen) in the "Grok endpoints" panel → test → chat with the Grok engine. Model specs use `provider/model-id` format (e.g. `glm/glm-5.2` — type any new model name via "Custom"). Add any OpenAI-compatible relay with the "+ Add custom endpoint" form (name, model ID, base_url, protocol, env var, key). Keys live in a 600-permission env file on the remote; the managed block in `~/.grok/config.toml` is auto-generated and never touches your own entries.
