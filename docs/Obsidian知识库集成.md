# Obsidian 知识库集成

把对话精华与每日速览沉淀成 **原子笔记 + [[双链]] + 主题索引(MOC)**,让 Obsidian 的图谱视图自然长出来。

## 为什么是"原子笔记 + 双链 + MOC"

把整段对话原样存成一篇长笔记,图谱里只会多一个孤点,没有意义。真正能形成知识网络的做法是:一个概念/结论 = 一篇短笔记,笔记之间用 `[[双链]]` 互指,再由一篇主题索引(MOC)汇总入口。本集成就是按这个结构生成的。

## 配置

设置 → **Obsidian 知识库**,两种写入方式任选:

**直写 vault 目录(推荐)** —— vault 本来就是一堆 markdown 文件,应用直接写进去,零插件零配置。点「选择…」挑你的 vault 根目录即可。

**Local REST API 插件** —— 在 Obsidian 装 [obsidian-local-rest-api](https://github.com/coddingtonbear/obsidian-local-rest-api),填地址(默认 `http://127.0.0.1:27123`)和插件里的 API Key。好处是远程运行的 codex 也能读写 vault;该插件现在还自带 MCP server。

「落地子目录」决定笔记写到 vault 的哪个文件夹(默认 `RemoteAgentStudio`)。配好点「测试连通与可写」确认。

## 用法

**存对话** —— 对话页头部的 🧠 按钮:当前引擎会把整段对话提炼成若干原子笔记(标题、摘要、要点、双链、标签),写入 vault 并更新 MOC。

**存速览** —— 速览页的「🧠 存入知识库」:把当天的资讯/创意/论文/开源项目归档成一篇带真实链接的日报笔记。

写完打开 Obsidian,图谱视图里就能看到新节点与连线。

## 安全边界

写入路径经过多层净化:文件名去掉 `/ \ : * ? " < > | # ^ [ ]` 与 `..`,子目录逐段净化,最后还会用绝对路径复核目标确实在 vault 内,任何越界写入直接拒绝。API Key 用系统 safeStorage 加密存本机,不回显、不进日志。

MOC 采用**标记块增量合并**:只重写 `<!-- ras:auto-index:begin/end -->` 之间的内容,块外你手写的段落原样保留,重复条目不会重复收录。

## 每日自动沉淀(无感知积累)

设置 → Obsidian 知识库 → **每日自动沉淀**:打开开关、设个时间(默认 22:00),之后不用再管。每天到点自动把当天对话里的**可复用经验**提炼进知识库。

**只沉淀有价值的**:踩过的坑与解决办法、技术决策与取舍、可复用的方法/配置/命令、结论性认知。寒暄、流水账、没结论的尝试会被明确排除;当天确实没什么可沉淀的就返回空,不硬凑。

**追加而非覆盖**——这是持续积累的关键。已存在的笔记会按日期追加「## 补充 YYYY-MM-DD」块,你在 Obsidian 里手写的批注**完整保留**;已经记过的要点自动跳过,同一条经验不会反复堆积。

**图谱会越长越密**:每次抽取都会把已有笔记标题喂给模型,要求同一概念必须复用相同标题、优先建立双链,而不是每天造新词。这样节点才会互相连起来,而不是碎成一地孤点。

**成本可控**:抽取是总结类任务,固定用便宜的小模型即可(默认 `minimax/minimax-m2.5`,也可换 `deepseek/deepseek-v4-flash` 等)。一天只跑一次。

**不怕关机**:应用当时没开着不会丢——下次启动会自动补跑当天遗漏的那次。失败也是静默的,只在设置里记录状态,第二天照常再试。

### 三个入口(都在「图谱」页顶部的状态条上)

**开启自动沉淀** —— 开启前会自动做前置条件自检(vault 是否可写、目标主机上抽取引擎的 CLI 是否装好),缺什么直接告诉你,避免到点了才静默失败。

**沉淀今天** —— 立刻把当天对话提炼一次,用来验证效果。

**沉淀全部历史** —— 一次性把**所有历史对话**回溯提炼进知识库,包括:

- 本应用内的全部对话(所有主机)
- **各个项目下 Claude Code / Codex CLI 的历史会话**(`~/.claude/projects/` 与 `~/.codex/sessions/`)——这部分往往才是经验的大头,工具调用和报错修复过程都在里面

点击后会先列出扫到多少段应用对话、多少个 CLI 会话、覆盖几个项目(含项目名与会话数),确认后才开始。

> 注意:CLI 的 jsonl 是内部格式,官方说明会随版本变化。解析全程防御式处理——认字段不认版本、坏行跳过、过短会话过滤,任何解析失败都不会中断整体沉淀。这是从零建立知识库最快的方式:点下去会先告诉你有多少段对话、约多少万字、要分几批调用模型,确认后才开始。

回溯按字符预算分批(每批约 2 万字),避免单次提示词过长被截断;**每批之间都会刷新已有笔记标题**,所以后面批次能链到前面新建的笔记上,而不是各批各自造孤点。单批失败会跳过并继续,不会让整个回溯前功尽弃。进度实时显示在状态条上。

## 知识图谱(查看与管理)

侧边栏「🕸️ 图谱」页,直接读你的 vault 渲染出知识网络。

**可视化**:力导向布局,节点大小按连接数,滚轮缩放、拖拽移动、点击查看。悬停会高亮该节点的所有邻居并淡化无关部分,方便看清一个概念的关联范围。索引(MOC)节点是紫色,**孤立笔记标红**——一眼就能看出哪些内容没连进网络。

**健康度统计**:顶部显示笔记数、双链数、孤立数、断链数、标签数。这两个数字最值得关注:

- **孤立笔记多** = 图谱没长起来,多半是每次沉淀都在造新词而没复用已有标题
- **断链多** = 模型编了不存在的笔记名,或笔记被改名/删除后引用没跟上

**管理**:按标题搜索、按标签筛选、只看孤立笔记;选中笔记后可查看正文与全部反向链接(可点击跳转)、在 Obsidian 里打开、移到废纸篓(不是直接删除,可恢复)。断链清单单独列出,方便逐个修。

范围可切「整个 vault」或「只看本工具目录」,后者用来单独观察自动沉淀的成果。扫描会跳过 `.obsidian`、`.trash` 等目录,并有 5000 文件上限保护。

## 已知取舍

**手动**存入(🧠 按钮)是覆盖同名笔记;**每日自动沉淀**是追加合并、保留手改。两者行为不同,是刻意的:手动那次你通常想要一份干净的重新提炼,而自动积累必须保住历史。若你手改过某篇笔记又想手动重存,建议先重命名。

提炼质量取决于模型。若发现笔记拆得过碎或标题像句子,可以调整 `electron/obsidianNotes.js` 里 `buildExtractPrompt` 的要求(那里明确写了"title 用名词性短语、宁可少而精")。
