# 长任务检查点

远程执行的长任务最常见的死法不是做错,而是**做到一半断了,重连后不知道做到哪**。

## 开工前:拆分并落盘

把任务拆成 3-8 个**可独立验证**的检查点,写进文件而不是只放在脑子里:

```bash
cat > .agent-progress.md <<'EOF'
# 任务:<一句话目标>
## 检查点
- [ ] 1. <做什么> —— 验证:<怎么算这步成了>
- [ ] 2. ...
## 已知约束
- <不能碰什么 / 必须保持什么不变>
EOF
```

拆分标准:**每个检查点结束时,代码都处于可运行状态**。不要留下"改了一半"的中间态。

## 每步结束:立刻更新

```bash
sed -i.bak 's/- \[ \] 1\./- [x] 1./' .agent-progress.md
```

同时把关键上下文追加进去 —— 断线重连后你看不到之前的对话,只看得到这个文件:

```markdown
## 进度记录
- 步骤1 完成:改了 src/a.js:42,原因是 X。验证:npm test 220 passed
- 步骤2 卡住:Y 报错 Z,怀疑是 W,下一步试 V
```

## 恢复:先读再动

被中断后重新开始时,**第一件事是读进度文件**,不是重头做:

```bash
cat .agent-progress.md 2>/dev/null && git status --short && git diff --stat
```

三个信息合起来就能还原现场:计划到哪、工作区有什么没提交的改动、改了多大范围。

## 大批量处理

处理很多文件/很多条数据时,单独记录已完成清单,支持断点续跑:

```bash
# 跳过已处理的
comm -23 <(ls *.txt | sort) <(sort done.txt 2>/dev/null) | while read f; do
  process "$f" && echo "$f" >> done.txt
done
```

**不要**把整批塞进一次操作里 —— 断在第 900 个,前 899 个也白做。

## 收尾

任务真正完成后清理临时文件:

```bash
rm -f .agent-progress.md .agent-progress.md.bak done.txt
```

但**先确认**完成:所有检查点打勾,且最终验证通过。没验证就别清,那是你的断点。
